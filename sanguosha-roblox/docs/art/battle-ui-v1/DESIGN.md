# 演武 UI · 第一版

2026-09-13。独立的美术交互原型，入口 `preview/battle-ui/`。沿用已有武将 3D 数据和卡牌原画。正式回合逻辑由玩法任务接入。

## 视觉方向

青灰场地、深青半透明底板、暖金操作高亮。大面积留给真实 3D 武将；边框只用于区分信息层级和可操作区域。宋体用于武将、牌名和重点指令，屏幕黑体用于规则、数量和提示。杀、闪、桃的术语分别使用暖红、浅青和草绿，同时保留文字，不依赖颜色判断。

| Token | 值 | 用途 |
| --- | --- | --- |
| ink | #101D1B | 场景与界面底色 |
| panel | #13221F / 95% | 信息抽屉与说明 |
| paper | #F6EDCF | 主要文字 |
| muted | #A4B7A8 | 次要公开信息 |
| gold | #E4BC72 | 已选目标、确认、当前阶段 |
| jade | #80C1A1 | 自己与恢复 |
| red | #ED8A73 | 杀与攻击提示 |

## 布局

桌面顶栏显示轮次、场次、帮助和重置；三名对手的头像横列在上方，包含武将名、体力、手牌数量与独立详情按钮。中间是四位可动武将与自己的阵位。左侧保留短战况。左下为自己、技能说明与公开装备，底部中间是扇形手牌，右下为确认、取消、结束。

手机保留同一层级：顶部三名对手压缩成小卡，底部自己信息变横条，手牌变为可横滑单列，底边固定操作条，左侧摇杆位于手牌上方。超过七张手牌时桌面也提供滚动，避免不断挤小牌名。选中卡抬起并描金，长卡名单独使用较小字号。低高度桌面与手机横屏将出牌提示移到左侧，给武将和头顶名字留出空间。

## 已实现的界面状态

| 状态 | 可操作内容 | 退出 / 下一步 |
| --- | --- | --- |
| 待选牌 | 移动、查看人物、看自己技能与装备 | 选择手牌 |
| 选单目标牌 | 杀 / 过河拆桥；目标有「可选」标记 | 点人物或顶部头像选目标，确认 |
| 多目标 | 铁索连环；最多两个有序名字槽 | 再点取消该目标；选第三人替换第二位，保留第一位 |
| 群体 | 万箭齐发；逐个标出三名其他角色 | 一次确认，不用一个大范围圈冒充规则 |
| 查看公开信息 | 头像旁 ⋯；可展开装备的完整效果 | 关闭时保留当前选牌与目标 |
| 选择区域牌 | 过河拆桥的手牌牌背或公开装备 | 只记录选取反馈，未知牌不显示牌面 |
| 响应 | 帮助菜单 / 结束出牌后进入出闪示例 | 仅闪可选；明确提供放弃响应 |
| 公开牌池 | 五谷丰登示例显示五张公开牌 | 点击一张加入演示手牌 |
| 使用反馈 | 牌名浮现、武将动作、战况、手牌移除 | 回到待选牌 |
| 拖牌 | 鼠标拖动；手机向上提牌，左右滑动仍用于手牌滚动 | 合法武将头顶松手使用；空白或非法目标松手收回 |

拖动使用独立草稿，悬停时显示合法目标边框、目标高亮与松手提示。无效放下、Esc、指针取消或窗口失焦不消耗手牌，也不覆盖原来的点击选牌与目标。拖放和点击确认复用同一使用流程，避免松手后的 click 再次触发。鼠标移动 8 px 后开始拖动；触屏向上移动 12 px 后提牌，横向保留浏览器原生滚动。

杀拖到对方头顶直接使用。铁索连环第一次拖放只选第一人，并显示可选的第二目标槽；再点击或再拖补选第二人，最后统一确认。也可确认只连一人，目标槽的 × 可以移除已选角色；重复拖到同一人保持原选择，选第三人只替换第二位。过河拆桥松手后打开区域牌选择，选完才消耗。万箭齐发拖到任一对手时明确提示作用于所有其他武将。装备、桃与酒拖到自己；响应中的闪也拖到自己。当前无可用拖放目标的牌只允许收回，实际资格仍由正式玩法层提供。

演示中的头像状态、当前阶段、目标资格、装备列表和选牌结果使用固定样例。原型不会实现真实判定、伤害、扣牌同步、身份模式或完整回合；武将技能按钮只展示说明。移动边界属于演出场景的局部约束。

## 给玩法任务的接入约定

保留「查看详情」和「选目标」两个不同意图。没选牌时点击人物查看；选牌时点击人物选择；独立 ⋯ 始终查看详情。详情面板点击不穿透到场地，关闭也不清空出牌草稿。

推荐从服务端接收一个公开 view model：

```text
publicPlayers: [{ id, heroId, hp, maxHp, handCount, publicEquipment, publicJudgements }]
selfHand: [{ instanceId, cardId, suit, rank }]
interaction: { phase, sourceId, cardId, legalTargetIds, minTargets, maxTargets, allowedResponses }
```

UI 向玩法层提交选择牌、选择目标、确认、取消、请求查看、响应、选择公开牌等意图。正式目标资格、距离与身份可见性必须由玩法层提供。不要把对手具体手牌下发后仅通过 UI 隐藏；此原型的对手数据只含数量，没有具体牌面。

浏览器舞台 API 位于 `scene.js`，使用真实模型数据和固定相机。WASD / 摇杆在本地展示移动；不能直接作为 Roblox 服务器移动控制。Roblox 原生实现可按本页布局使用 ScreenGui、ScrollingFrame 和头部 BillboardGui，继续沿用已有正式角色控制。

## 交付文件

- `preview/battle-ui/index.html`：对局层级和可访问的按钮、抽屉、对话框。
- `style.css`：颜色、版式、卡牌状态、桌面与手机适配。
- `main.js`：固定公开样例与 UI 状态切换，不访问正式游戏服务。
- `scene.js`：四名武将、场地、局部移动和动作。
- 本目录的截图与 `browser-qa.cjs` / `browser-report.json`：交互与视觉验收记录。

原生手机、多人网络同步与正式玩法尚未验收。这轮交付为可体验的网页 UI 设计稿。

## 验收范围

浏览器操作检查覆盖初始 7 张手牌、需要目标才可确认、查看装备保持选牌、最多两个有序目标、未知区域牌选择、仅闪可响应、公共牌池选入手牌、重置、桌面键盘和手机摇杆。通过只读舞台快照检查局部半径、停止移动、弹窗期间输入隔离与网格缓存稳定。

拖牌专项用 `drag-qa.cjs` 检查真实鼠标与触屏拖动、原有点击操作、无效放下、取消、区域牌选择与手机横向滚动，结果写入 `drag-report.json`。`tiesuo-drag-qa.cjs` 另外覆盖补选第二人、重复拖放、替换第二位、删除目标槽与混用点击后统一确认。

布局分别检查 1440×960、1280×720、390×844 和 844×390。窄屏手牌横滑，短横屏收紧头像、手牌与操作条，并将舞台缩放到 HUD 留白区。`layout-report.json` 还覆盖销毁场景时 GPU 资源释放与模型加载失败提示。所有截图是该网页原型的实际渲染，不是 Roblox 原生运行截图。
